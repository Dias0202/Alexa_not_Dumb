# Release 0.1.2 — 2026-08-02

## Escopo

Correção do contrato da resposta de diálogo após a Alexa rejeitar a resposta da skill no Echo físico e no teste manual.

## Conteúdo entregue

- Remoção de `Dialog.ElicitSlot`, diretiva rejeitada pelo endpoint Alexa-hosted neste fluxo.
- Cada turno passa a usar a frase portadora `pergunte {pergunta}`, capturada por `AMAZON.SearchQuery`.
- Teste automatizado garante que o `LaunchRequest` não devolve diretivas de diálogo e mantém a sessão aberta.
- O carregamento de configuração e LLM ocorre apenas ao responder uma pergunta; se falhar, a skill devolve uma mensagem controlada.

## Validação necessária após o deploy

1. Diga: "Alexa, abrir meu assistente".
2. Confirme que a Alexa responde e mantém a sessão aberta.
3. Pergunte: "pergunte qual a capital de Minas Gerais".
4. Para uma nova pergunta, diga novamente "pergunte ...".

## Limitações

- A conversa exige a carrier phrase em todos os turnos; captura totalmente livre foi removida para evitar a diretiva incompatível.
- O console Alexa pode continuar apresentando defeito no campo visual do simulador; o Echo físico é a validação de voz definitiva.
- A resposta gerada depende das dependências da Alexa-hosted e das cotas do provedor LLM; uma indisponibilidade devolve fallback, sem encerrar a skill com erro de contrato.
- Essa correção não altera provedores, chaves ou custos.
